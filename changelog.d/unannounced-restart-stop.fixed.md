- A worker that you restart under the same nodename, and whose `worker_ready` the server never receives, now reads as stopped when it stops cleanly. Before, the server kept the old process listed as live, so the nodename stayed online in the Workers page and kept the `no_workers_online` alert off for up to 30 minutes after the stop. The server now treats a `worker_shutdown` for a process it doesn't list as the end of the nodename's listed process, when the shutdown is stamped at or after that process's latest `worker_ready`.
- A `worker_shutdown` stamped before the listed process's latest `worker_ready` now leaves that process online as a late stop of an older process. Before, a shutdown that named the listed pid always stopped it (for example, an older container process that had the same pid). For a nodename the server knows only from task events, or one that task events brought back after a stop, a shutdown stamped before its latest task event now leaves it online too. Before, any shutdown took it offline.
