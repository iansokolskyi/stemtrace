- Capturing task arguments no longer scrubs and serializes a whole value that is larger than `max_data_size`. The scrub charges each node its smallest output size and stops once the total passes the limit, so the cost depends on `max_data_size`, not on the size of the arguments. This holds for nested and wide lists and dicts, long strings and bytes, and tuple keys. Arguments under the limit are scrubbed in one pass, with no more key checks than before, and produce the same output. The marker for a value that the scrub cuts off reads `[Truncated: over N bytes > N max]`, because the full size is no longer computed. Custom `Mapping` or `Sequence` types and objects with a slow `__str__` are not bounded.
