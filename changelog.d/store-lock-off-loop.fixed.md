- Fix the server's event loop stalling while a request scans the task store. `/api/health`, `/api/tasks/{id}`, `/api/tasks/{id}/children`, `/api/graphs/{id}`, `/api/anomalies` and the summary routes no longer take the store lock on the event loop thread. During a hostname-filtered task list at 30,000 tasks (2 vCPU host), the longest loop gap fell from 415-474 ms to 49-87 ms and `/api/health` answered in 1-17 ms instead of 387-403 ms. A request that needs the store still waits for the lock, now in a worker thread, so its own latency still includes the wait.
