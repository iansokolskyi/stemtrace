- Scrubbing no longer filters dict values keyed by an `IntEnum`, `IntFlag` or `StrEnum` member (or any str- or int-mixin Enum) because of the member's name: `{HTTPStatus.UNAUTHORIZED: ...}` was filtered as if `401` were a credential, since the name contains `auth`. Such a key equals its value and is serialized as it, so it is now matched as that value: an int never, a str by its text (a `StrEnum` member whose value is `"authorization"` is still filtered). Such a key is also shown as that value (`"pw"` for `Field.PASSWORD = "pw"`), so a value that isn't filtered never appears under a member name that looks sensitive. An `IntEnum` member named like a credential (`Cred.PASSWORD = 2`) is no longer filtered, like any int key, and `additional_sensitive_keys` can't filter it. Other Enum members and Flag values still match by name.
