- `GET /api/workers` and `GET /api/workers/{hostname}` return `active`, the number of busy slots on each worker, counted from the run records that are still `STARTED` since the worker's current pid sent `worker_ready`. It is `null` for a worker that isn't the online, current process of its nodename. A run whose final event never arrived keeps counting, and a task whose `STARTED` event the server never received doesn't count (on RabbitMQ: events sent before the server's queue existed or older than its TTL; on Redis: events past the stream's retention).
