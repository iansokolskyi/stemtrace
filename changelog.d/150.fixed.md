- A FAILURE that Celery sends from a worker's main process (a hard time limit, a lost pool process) now carries its retry count, worker, queue and parent, root and group IDs, read from the failing request. Before, it said `retries=0` whatever the attempt and had none of the others.
- `runtime_ms` and `total_runtime_ms` pair each run's STARTED with the end event from the same worker and attempt, so for events from this release's workers a run is read on one worker's clock and skewed clocks between workers don't shorten or empty them. When one worker ran the same attempt twice (a redelivery to the same worker), both are empty instead of a guess. Events from older workers carry no worker, so they pair as before. See [Features: limitations](https://github.com/iansokolskyi/stemtrace/blob/main/docs/features.md#queue-wait-and-runtime).
