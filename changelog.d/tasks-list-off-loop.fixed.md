- `GET /api/tasks` and `GET /api/graphs` run their scan and build their response in a worker thread, so a single request no longer holds the event loop. With 30,000 runs of 10 events each, `GET /api/tasks?limit=500` did 402,596 profile events between two loop turns and now does 24,954; `hostname=worker3@host3` did 1,804,922 and now does 24,940; a cold `GET /api/graphs?limit=100` did 1,070,906 and now does 8,395. Where the host app's sync handlers fill the thread limiter, these two lists wait for a thread. Requests that overlap a long scan can still wait for the store lock. Responses are unchanged.
