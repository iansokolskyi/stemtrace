- `GET /api/tasks` and `GET /api/graphs` scan the store, build the response and encode its JSON in a worker thread, so a single request no longer holds the event loop. With 30,000 runs of 10 events each (10 KB `args`, `kwargs`, `result` and `traceback` payloads), `GET /api/tasks?limit=500` (a 27 MB body) took 137.9 ms of event-loop CPU in its longest turn and now takes 2.3 ms. A cold `GET /api/graphs?limit=100` did 1,070,906 profile events between two loop turns and now does 8,395. Where the host app's sync handlers fill the thread limiter, these two lists wait for a thread. Requests that overlap a long scan can still wait for the store lock. Response bodies are unchanged.
