- `GET /api/graphs` reads each flow's time from an index that the store updates as events arrive and as tasks move or are evicted, and snapshots only the listed roots (plus the members of a root group or chord). At 10,000 stored tasks a list of 50 flows takes about half a millisecond instead of about 50 ms (median, measured with the benchmark in the pull request).
- A task's time for the graph list never counts as later than when the server received its event, so a worker clock running ahead of the server's no longer keeps its flows on top of the list. A clock running behind still sorts its flows lower. The graph's own `first_seen` and `last_updated` aren't changed.
